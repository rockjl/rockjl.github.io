July 19, 2023

内存泄露

首先我们先来讲内存泄露，rust中有两种方式可以造成内存泄露。

  • 循环引用 如下的代码执行之后我们在控制台与系统监视器中监控进程执行过程，测试路程如下。
  1. 首先在控制台打印main function start的时候内存还未分配太多，索引进程占用内存还是很小的。
  2. 等到空太太打印start add mem以后，可以看到系统监视器中进程内存占用增加到了30多MB。
  3. 但是看到outside stack_alloc打印到控制台的时候并未在系统监视器中看到内存的释放，代表内存泄露了，并且drop函数也并未执行。 总结：本来在函数mem_alloc执行过后就应该回收内存了，第一：栈空间的回收，第二：堆空间的回收。由于我们使用了智能指针，内存大多分配在了堆空间，但是堆空间未回收是因为出现了循环引用。当我们把其中cur_node.borrow_mut().next = Some(first_node.clone());注释掉再次执行的时候就会看到内存的释放了
use std::cell::RefCell;
struct Node {
    index: u32,
    next : Option<Rc<RefCell<Node>>>
}
impl Node {
    fn new(index: u32) -> Node {
        Node { index, next : None}
    }
}
impl Drop for Node {
    fn drop(&mut self) {
        println!("drop Node:{:#?}", self.index);
    }
}
fn mem_alloc() {
    let first_node = Rc::new(RefCell::new(Node::new(0)));
    let mut cur_node = first_node.clone();
    for idx in 1..819200 {
        let next_node = Rc::new(RefCell::new(Node::new(idx)));
        cur_node.borrow_mut().next = Some(next_node.clone());
        cur_node = next_node;
    }
    cur_node.borrow_mut().next = Some(first_node.clone());//这行代码会造成循环引用，会造成内存泄露。
}
fn main() {
	println!("main function start");
    sleep(1000 * 10);
    println!("start add mem");
    
    mem_alloc();
    
    println!("outside stack_alloc");
    sleep(1000 * 10);
    println!("main function stop");
}

        cur_node.borrow_mut().next = Some(next_node.clone());
        cur_node = next_node;
    }

    // std::mem::forget(cur_node);
}

内存分配

当然这里也不用多说，rust的内存分配大家都知道分为堆和栈两种。

  • 堆 堆空间的内存分配需要使用智能指针的配合。像是Vec和String都是存储在堆中。
  • 栈 对于栈的分配我们需要来讲一讲。栈空间是有限的，为什么说有限，是因为栈空间是在当前线程的执行堆栈中分配内存，受限于当前线程的堆栈大小。(线程的默认堆栈大小可以直接修改操作系统的参数，如果是我们自己启动的线程可以在线程启动之前来修改)。 包括数组的初始化，我们可以发现rust对于数组的初始化，如果想在栈空间初始化过大的数组是一件很累的事情。如果手动在栈空间写出来了一个超大的数组，并且大小超过了当前线程执行的堆栈大小，进程在执行到需要在线程堆栈非配大量内存的函数的时候，在这个函数的位置会报错(注意：这里不是panic。是报错：EXC_BAD_ACCESS(code=2, address=0x7ff7bf700600。我的是mac，其他的操作系统错误也只是大同小异罢了。下面代码如果在某些人电脑上面没有出现错误，可以复制大量的new_obj代码行。一定会出现的。))。

内存回收

对于内存的回收有两个维度需要讲。一个是堆，一个是栈。 我们带着问题来深入的探讨一下rust的内存回收。

  1. drop函数何时执行？
  2. 堆栈的数据何时回收内存？

先看一段完整的代码。然后我们再来一点一点的修改。

#[derive(Debug)]
struct Obj {
    name: String,
    index: u32,
    option: [u32; 81920],
}
impl Drop for Obj {
    fn drop(&mut self) {
        println!("drop.Obj:{:?}", self.index);
    }
}
fn new_obj(name: String, index: u32, option: [u32; 81920]) -> Obj {
    Obj { name, index, option }
}
fn mem_alloc() {
    println!("mem_alloc start");
    let obj = new_obj("rockjiang".to_string(), 11, [1101; 81920]);
    //let obj = Box::new(new_obj("rockjiang".to_string(), 11, [1101; 81920]));
    {
        let obj = new_obj("rockjiang".to_string(), 22, [1101; 81920]);
        //let obj = Box::new(new_obj("rockjiang".to_string(), 22, [1101; 81920]));
    }
    println!("mem_alloc stop");
}
fn test_mem_recycling() {
    println!("test_mem_recycling function start");
    sleep(1000 * 10);
    println!("start add mem");
    mem_alloc();
    println!("outside stack_alloc");
    sleep(1000 * 10);
    println!("test_mem_recycling function stop");

我们下面分为两个维度来深入的探讨。

堆

我们修改mem_alloc函数

fn mem_alloc() {
    println!("mem_alloc start");
    let mut v = Vec::new();
    for idx in 0..8192 {
        v.push(new_obj("rockjiang".to_string(), idx, [1101; 81920]));
    }
    println!("mem_alloc stop");
}

可以在控制台配合系统监视器的情况下，看到程序在进入mem_alloc函数和推出mem_alloc函数的时候内存的突增和消失。这证明了堆内存实在函数的退出的时候释放的。 我们再来改一下：

println!("mem_alloc start");
    {
        let mut v = Vec::new();
        for idx in 0..8192 {
            v.push(new_obj("rockjiang".to_string(), idx, [1101; 81920]));
        }
    }
    println!("outside code block");
    sleep(1000 * 10);
    println!("mem_alloc stop");

这次我们可以清晰的看到在控制台输出outside code block的时候，系统监视器中进程的内存被大量回收了。被来占用单位上GB的内存瞬间跌落在了几个MB级别。那么也就是说在堆空间代码块的结束也可以让内存回收，并且drop函数的执行。 那么我们继续修改代码。

println!("mem_alloc start");
    let mut v = Vec::new();
    for idx in 0..8192 {
        v.push(new_obj("rockjiang".to_string(), idx, [1101; 81920]));
    }
    std::mem::forget(v);
    println!("mem_alloc stop");
}

这次不管如何我们看到了内存泄露。我们第一个内存泄露也分析了这种情况。内存在堆的时候并且被std::mem::ManuallyDrop包裹的时候，会造成内存泄露。

栈

对于栈空间的测试修改的比较大，我重新粘贴代码。由于需要更大的栈空间来做测试，所以我们新建了一个更大堆栈空间的线程来执行指定的代码。来详细的跟踪一下代码的执行情况与内存的回收情况。

fn mem_alloc() {

    let arr = [
        new_obj("rockjiang".to_string(), 22, [1101; 81920]),

        new_obj("rockjiang".to_string(), 22, [1101; 81920]),
        //...此处省略很多行。请复制N行出来。堆栈不够大的自行调整。
    ];
    std::mem::ManuallyDrop::new(arr);//这里即便把数据使用ManuallyDrop包裹，仅仅会造成逻辑回收的内存泄露，但是不会阻挡当线程销毁时候的物理回收的执行。最终结果并不会造成真实的内存泄露。
    sleep(1000 * 10);
    println!("mem_alloc stop");
}
fn test_mem_recycling() {
    println!("test_mem_recycling function start");

fn sleep(t: u64) {
    std::thread::sleep(std::time::Duration::from_millis(t));
}
fn new_thread() {
    let jh = std::thread::Builder::new().stack_size(8192000000).spawn(|| {
        test_mem_recycling();
    }).unwrap();
    
    jh.join().unwrap();

从上面代码的执行，可以看出。栈空间的申请，是在对应函数执行的时候就会申请了。但是内存的回收确是在执行函数对应的线程销毁的时候。 我们继续修改上面的代码：只修改两个函数。

fn mem_alloc(ptr: &mut Option<*const Obj>) {
    println!("mem_alloc start");
    let obj = new_obj("rockjiang".to_string(), 22, [1101; 81920]);
    *ptr = Some(&obj as *const Obj);
    sleep(1000 * 10);
    println!("mem_alloc stop");
}
fn test_mem_recycling() {
    println!("test_mem_recycling function start");
    sleep(1000 * 10);
    println!("start add mem");

    let mut ptr = None;
    
    mem_alloc(&mut ptr);
    
    unsafe {
        if let Some(p) = ptr {
            println!("ptr={:?}", *p);
        } else {
            println!("None");
        }
    }
    
    println!("outside stack_alloc");
    sleep(1000 * 20);
    println!("test_mem_recycling function stop");
}

总结

  1. 栈内存的分配是在函数调用的时候，函数那需要多大的栈空间那么就需要申请多大的内存空间。注意这里是函数调用的时候，而不是代码块调用的时候。
  2. 栈内存的回收是在堆栈所在线程销毁的时候。不管在控制台查看还是在系统监视器中查看，都是这个结果。
  3. 堆内存的分配是在代码调用的时候，准确的说是哪里调用了代码哪里就分配了内存。
  4. 堆内存的释放是在数据所有者所在作用于结束的时候即刻回收内存。
  5. 如果使用了std::mem::ManuallyDrop。栈内存还是在线程销毁的时候回收内存。堆空间内存则会造成泄露。
  6. 注意：数据不管是在堆还是在栈，被回收的内存都有可能处于无法访问的状态。有些同学尝试使用unsafe访问被回收的内存地址，如果数据在栈，并且当前线程还未销毁的情况下，还不会有问题。但是如果数据在堆，就很有可能会报错。造成程序的终止
