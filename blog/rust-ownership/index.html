所有权

在rust中，每一个value都有一个var也就是变量(所有者)，这时这个var对于这个value具有所有权。 所有权可以：move。 所有权可以：borrow。

  1. 在rust中也类似c中一样，把值分别存储在stack中和heap中。 在stack上的变量彼此的赋值属于值传递。当然了并不代表变量对于值不具备所有权。
   let a = 32;
   let b = a;

如果变量存储在heap中，普通的赋值语句则属于对于heap中value所有权的move。也就是移动。下面代码回报错。因为所有权已经被转移到b上，即便显示的调用drop函数销毁b，所有权也不会返回到a。

   let a = "hello".to_string();
   let b = a;
   //drop(b);
   println!("{}", a); //value borrowed here after move

  1. 在rust中每一个值都有对应的一个主人(就是它的变量，也是这个值的所有者)。

  2. 在rust中每一个值同一时间只能有一个所有者。

  3. 当变量离开作用域或者移交所有权，变量将会自动被系统调用drop函数销毁。

  4. 变量之间的赋值，对于heap中的数据来讲，就是移交了所有权，这里包括向函数内传递数据。

  5. 一个引用不会拥有值的所有权，它对于值的所有权属于借用关系。

  6. 借用也分为完全借用和部分借用，完全借用就是把读写权限全部借用过来，部分借用就是只读权限的借用。

  7. 只有一个可变的变量，才可以创建一个可变的引用。一个不可变的变量是无法创建一个可变引用的。 这里所说的引用，就是一个变量。这个变量对于原有的普通变量对应的值，就是一种借用的关系。 如下代码将会报错。

   let a = 11;
   let b = &mut a;
  1. 对于一个可变变量来讲，同一时间不可以拥有多个可变引用。但是可以拥有任意数量的不可变引用。
   let mut a = 11;
   let b = &mut a;
   let c = &mut a; //cannot borrow `a` as mutable more than once at a time
   println!("{}", b);

  1. 引用必须一直有效。如果编译器无法确定引用的有效作用域，就需要使用生命周期注释加以标注。

  2. 如果一个可变变量，被借用为不可变引用的时候，这时如果修改可变变量的值，刚刚被借用的不可变引用将会失效，需要重新续租，详细的借用规则看下面。

借用的细节:& 与 &mut 与 mut = &mut 的区别

  • 对于不可变所有权的借用，可以随便使用，因为不可遍所有权仅仅只是只读，不具备写属性。
  	let a = 5;
      let b = &a;
      println!("{}", a);
      println!("{}", b);
  • 对于可变变量的不可变借用，可变变量是读写属性，不可变所有权的借用是只读属性，当借用后，修改可变变量的值，之前不可变所有权的借用将失效，如果***行的存在，这a=11这一方将会报错。否则不会报任何错误。如果想在a值被修改后，继续使用不可遍所有权，必须续租，也就是重新借用。
  	let mut a = 5;
      let b = &a;
      println!("{}", a); 
      println!("{}", b); 
      a = 11;                //会报错cannot borrow `a` as immutable because it is also borrowed as mutable
      println!("{}", a); 
  	//let b = &a;		   //续租
      println!("{}", b);     //<<***
  • 对于可变变量的可变所有权借用，所有权会被完全借走。如下代码会报错，因为所有权已经被完全借走，如果继续使用a则会报错。当b销毁的时候才可以归还所有权，这里可以显示的使用drop函数，但是一旦b销毁，后面也不可以继续使用b这个变量了。 这个错误的发生也是有一个先决条件的，也就是当b销毁前，在决定使用a之后还在继续使用b，这个时候，编译器会认为b的一个都在借用a的全部所有权，这个时候a不可以继续使用。所以会报错。
  	let mut rr = 0;
      let mut a = 5;
      let b = &mut a;
      //drop(b);
      rr = rr + a; //会报错cannot borrow `a` as immutable because it is also borrowed as mutable
      rr = rr + *b;
  • 对于可变变量的可变所有权借用，问题二。单可变所有权的变量的所有权被完全借走以后，不能以任何方式使用这个变量。
  	let mut a = 5;
      let b = &mut a;
      println!("{}", b);
      a = 10;                 //cannot assign to `a` because it is borrowed
      println!("{}", b);
      println!("{}", a);
  • 对于可变变量的可变所有权借用。问题三。毕竟已经是可变所有权的借用了，所以肯定允许修改变量的值所以说，是允许通过变量b来修改。但是不允许改变可变所有权变量的指向。除非可变所有权变量，也就是b，是mut的。这个时候是允许修改的。
  	let mut s1 = "hello".to_string();
      let mut s2 = "world".to_string();
      //let b = &mut s1; //<< 变量b是否为mut的
  	let mut b = &mut s1; //<< 变量b是否为mut的
      *b = "woleigequ".to_string();
      b = &mut s2;	//cannot assign twice to immutable variable `b`
  • 最后一个对于函数的传递，不管是可变所有权的借用，还是非可变所有权的借用，在函数结束的时候都会销毁，所以不用考虑细节问题。
举了这么多借用的例子，可以看得出借用这块还有几条规则： 1. 所有权分读所有权，和写所有权。2. 如果精通java多线程的小伙伴会感受到所有权有点类似读写锁，也就是ReentrantReadWriteLock，同一时间只允许一个写，但是同一时间可以拥有不限额数的读。
